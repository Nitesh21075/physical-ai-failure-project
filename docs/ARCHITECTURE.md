# Architecture

## High-level loop

```text
                Experiment memory
                       |
                       v
                Scenario Agent
                       |
                 Scenario spec
                       |
                       v
                 Orchestrator
                       |
                 Robot Controller
                       |
                    action
                       |
                       v
                 Environment
                  /        \
                 /          \
          Isaac Sim       Neural WM
                 \          /
                  \        /
                   observation
                       |
                       v
                    Evaluator
                       |
              trajectory + result
                       |
                       v
                 Experiment log
                       |
                       +------> next experiment
```

## Environment abstraction

The core harness should not know whether it is interacting with Isaac Sim, a neural world model, or a test/mock environment.

Conceptually:

```python
class Environment:
    def reset(self, scenario): ...
    def step(self, action): ...
    def observe(self): ...
    def close(self): ...
```

Actual implementation can be synchronous or asynchronous depending on the backend.

The interface should support enough metadata to record:
- observation(s)
- action
- timestamp/simulation time
- terminal state
- optional structured world state
- optional video/sensor references

## Scenario

Scenarios should be structured and constrained rather than arbitrary code generated by an LLM.

Example:

```json
{
  "environment": "industrial_warehouse",
  "task": "reach_target",
  "hazards": {
    "smoke": 0.7,
    "fire": true,
    "falling_beam": "beam_2"
  },
  "blocked_route": "east",
  "seed": 18273
}
```

The exact schema will evolve with the chosen demo.

## Memory

Use bounded structured experiment memory.

Do not send an entire video history to an LLM on every iteration.

A useful memory record contains:
- scenario parameters
- initial conditions
- summary of actions
- outcome
- environmental consequence
- failure category
- relevant metrics
- links/paths to raw trajectory artifacts

The scenario agent can receive a compact summary plus selected visual evidence when visual reasoning is useful.

## Failure evaluation

The evaluator should distinguish:

1. task success/failure;
2. robot safety events;
3. environmental consequences;
4. severity;
5. terminal/catastrophic events.

Example:

```json
{
  "task_success": true,
  "environmental_failure": true,
  "failure_type": "structural_collapse",
  "severity": "high"
}
```

This is intentional: a robot can complete its action while causing an environmental failure.

## Data

Prefer small structured metadata plus references to large artifacts.

```text
runs/
  <run_id>/
    scenario.json
    trajectory.jsonl
    result.json
    media/
```

Do not commit generated media or simulator caches to Git.

## World-model role

The exact role depends on the API actually available.

### If a closed-loop robotics world model is available

Use:

`observation + action -> next observation`

The neural world model becomes the environment backend.

### If only a generative video world model is available

Use it as a visual counterfactual/augmentation backend. Do not treat generated video as authoritative physical state.

### If both neural and physics environments are available

Run equivalent experiments and compare:
- observations/visual trajectories
- robot outcomes
- environmental consequences
- failure timing
- state discrepancies where structured state exists

## Plan C comparison

Plan C should be implemented outside the core environment interface:

```text
Scenario
   |
   +----> Isaac Sim ----> trajectory A
   |
   +----> Neural WM ----> trajectory B
                         |
                         v
                    Comparator
                         |
                 discrepancies/failures
                         |
                         v
                    research log
```

The comparator should not assume that the two backends expose identical state. Compare only aligned quantities, with visual/semantic comparison where necessary.
